## P1 — UX/UI, přístupnost, responzivita, výkon (před masovějším vydáním)

- [ ] **P1-01 WCAG 2.2 AA — audit všech scénářů, nejen kontrastu.** `qa:contrast` měří vykreslený kontrast; `qa:tvary` měří ovládací prvky, `qa-site` používá Chromium/WebKit. **Nejde o kompletní AA posouzení.** Testovat logickou klávesovou navigaci, fokus dialogů/návrat, VoiceOver/Safari WKWebView, NVDA/Chrome, živá hlášení, jména a role, viditelný fokus a jeho nezakrytí, labely/errors, reduced motion, barvy, zmenšení textu. Cíle ≥24×24 CSS px nebo zdokumentovaná výjimka dle SC 2.5.8; fokus nezakrytý sticky/floating UI (2.4.11), ne pouze screenshot. [#217](https://github.com/martin-pok/agentree/issues/217)

## P2 — diferencující produkt a power-user workflow (jen po release + výzkumu)

- [ ] **P2-01 Attention Inbox místo zahlceného dashboardu.** Souhrn `needs_decision / failed / limit / stale` se sdružením duplicit, odložením, potvrzením, prioritou a **jedním klikem zpět k původní session**. Navázat na existující Upozornění. Měřit time-to-unblock.
- [ ] **P2-02 Multi-agent saved views.** Uložené filtry projekt/tool/status/zdroj/aktuálnost pro 20–50 sessions, keyboard-first navigace a existující command palette jako hlavní ovládací vrstva; nepřidávat druhou paletu.
- [ ] **P2-03 Source confidence / freshness.** Ke každému statusu uvést původ (hook, API, přepis, proces, extension), stáří posledního eventu a míru jistoty. Žádné „pracuje“ z historicky starých dat.
- [ ] **P2-04 Reviewer bridge do Gitu.** Propojit existující `src/git.js` / worktrees, stav úlohy s diffem, skutečnými CI checks a PR. Reuse namísto samostatného plnohodnotného IDE; vždy přiznat oprávnění.
- [ ] **P2-05 Performance-aware orchestrace.** Volitelný přehled konkurence běhů, resource pressure a čekání na lidské rozhodnutí. Na přepínání modelů nebo agentů jen zdokumentované, bezpečné a explicitní akce.
- [ ] **P2-06 Truthful spend controls.** Limit předplatného ≠ API faktura; lokální přepis tokenů ≠ cena; odhady oddělit od faktických API nákladů; zdroj a stav synchronizace viditelně.
- [ ] **P2-07 Automation / API / MCP.** Až po threat modelu: akce `open / acknowledge / start-approved / show-status` s per-action scopes, potvrzením, revokací a bezpečným protokolem (bez tajemství). Nepřidávat implicitně vzdálené spouštění shellu.
- [ ] **P2-08 Onboarding/activation.** Bez účtu a v 2–3 krocích zjistit první užitečný *ověřený* agent; nulový stav, nenalezené nástroje, nespojené rozšíření a recovery mají skutečné CTA. Měřit task-based UAT s 5–10 lidmi; bez skryté analytiky.
- [ ] **P2-09 Go-to-market.** Reálný product demo flow, aktuální CZ/EN Store screenshoty, srozumitelná privacy a příklad reálné hodnoty. 10 interview; teprve potom pricing/free vs Pro, retence a placená nabídka.
- [ ] **P2-10 Team / iOS.** Konkurence má vzdálené workspace, cloud sandboxy a multiplayer; naší obranou musí být bezpečný local-first dohled a skutečně užitečné mobilní upozornění, ne další nekontrolovaný cloud s přepisy. Teprve po měření poptávky navrhnout team tenancy, E2EE a permission model. [#219](https://github.com/martin-pok/agentree/issues/219)

## Řazení práce a Definition of Done

**Pořadí:** (1) dokončit v0.46.11 zařízení UAT + schválenou veřejnou Preview distribuci, (2) synchronizovat skutečný Chrome Store s Mac buildem, (3) WCAG/formální a mobile+PSI + live connectors evidence, (4) opravovat jen reprodukovatelné P1 vady a performance, (5) ověřit power-user hypotézy a teprve pak rozšiřovat produkt.

Každá karta má **owner, přesné SHA, kroky reprodukce nebo výzkumnou hypotézu, prioritu, dopad, dotčené platformy, důkaz, test a exit criteria**. Hotovo = kód review + automatické regresní testy + relevantní Chromium/WebKit/Mac/Windows UAT + soulad CZ/EN + dokumentace + podle významu bezpečnostní audit + potvrzené nasazení. **„Bezchybnost 100 %“ nelze garantovat; lze udržovat nula známých kritických závad a jasný důkaz kvality.**

**Průběžný benchmark**: cíleně porovnávat čas zjištění čekajícího agenta, čas návratu do session, úspěšnost párování, počet zmeškaných upozornění, pravdivost údajů, dobu první hodnoty, spolehlivost update procesu a uživatelskou spokojenost. Conductor/Superset nabízejí izolované worktrees, diff review a paralelní agenty; diferenciace Agenteeq má být *cross-tool situational awareness + důvěryhodná data + local-first privacy*, nikoli přepsaný terminál.
